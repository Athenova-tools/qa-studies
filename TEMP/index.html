Prompt — Página de Donativos do Projeto com Integração PayPal (pt-PT)

1. Objetivo do Projeto

Criar uma página de donativos moderna, profissional e responsiva, em português de Portugal, que permita aos visitantes apoiar financeiramente um projeto digital independente.

A página deve permitir doações para uma conta PayPal específica, com montantes predefinidos ou valor livre introduzido pelo utilizador.

Deve transmitir confiança, transparência e agradecimento a qualquer contribuição, independentemente do valor. Nome do projeto: [PROJECT_NAME].

2. Funcionalidade de Donativos

Montantes predefinidos

Apresentar opções selecionáveis, por exemplo:

  • €2 — Pequena contribuição
  • €5 — Apoiante
  • €10 — Colaborador do projeto
  • €25 — Campeão do projeto
  • €50 — Apoiante principal
  • Valor livre — introduzir qualquer montante

Os valores devem ser configuráveis e fáceis de alterar. Apenas um montante predefinido pode estar selecionado de cada vez; escolher "valor livre" ativa o campo de entrada.

Valor livre

Campo numérico para o montante à escolha do doador:

  • Moeda por omissão: EUR (€)
  • Validar antes de redirecionar para o PayPal
  • Rejeitar vazio, zero, negativo, não numérico e valores abaixo do mínimo configurável
  • Mostrar claramente o montante selecionado antes da saída para o PayPal
  • Nunca cobrar automaticamente nem recolher dados de pagamento no site

Integração PayPal

  • Conta PayPal do projeto: [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID]
  • Moeda: EUR
  • Montantes e mínimo: configuráveis

Usar uma integração oficial suportada (PayPal Donate, se disponível para a conta, ou outra solução oficial do PayPal Checkout que permita definir o montante).

Fluxo obrigatório:

  1. Selecionar montante → 2. Mostrar resumo da doação → 3. Redirecionar/abrir a interface oficial do PayPal → 4. O doador conclui ou cancela → 5. Retorno a página de sucesso/cancelamento, quando suportado.

Proibido: simular pagamentos bem-sucedidos ou mostrar confirmação antes de o PayPal confirmar. Proibido: expor credenciais secretas no frontend. Verificar previamente as capacidades reais da integração escolhida (o link PayPal.me não serve para todos os casos).

3. Design da Página

Layout limpo, tipografia profissional, espaçamento generoso e identidade visual consistente com o projeto existente (reutilizar o design system atual se existir).

A. Hero

Título: "Apoia o Projeto. Ajuda-o a Crescer."

Texto de apoio: "Cada contribuição ajuda-nos a melhorar, manter e expandir este projeto. Escolhe um valor que faça sentido para ti e ajuda-nos a continuar a construir algo valioso."

CTA primário: "Apoiar o Projeto"

B. Seletor de donativo

Cartões/botões visualmente distintos, cada um com montante, descrição curta, estado selecionado claro e interação acessível + campo de valor livre + botão proeminente "Continuar com o PayPal".

C. Porque o teu apoio importa

Ex.: desenvolvimento de novas funcionalidades, manutenção e melhorias, custos de alojamento, criação de ferramentas adicionais. Só afirmar despesas ou compromissos específicos se forem verdadeiros e aprovados pelo dono do projeto.

D. Confiança e transparência

Frase curta: os pagamentos são processados pelo PayPal e o site não recolhe nem guarda dados de cartão. Indicar se as doações são voluntárias e se oferecem algum benefício. Não afirmar dedutibilidade fiscal sem verificação.

E. Agradecimento

Estado/página de agradecimento: "Obrigado por apoiar o projeto. A tua contribuição é muito apreciada." — mostrar apenas após confirmação fiável do PayPal; caso contrário usar linguagem neutra ("Obrigado pela visita à nossa página de donativos"). Botão de regresso ao site principal.

4. Requisitos Técnicos

  • Responsivo (desktop, tablet, mobile), acessível e navegável por teclado
  • Validação e mensagens de erro claras
  • Processamento seguro via PayPal; sem armazenamento de dados de cartão
  • Sem confirmações falsas; sem recolha desnecessária de dados pessoais
  • Título e meta tags SEO-friendly; assets leves e carregamento rápido
  • Código reutilizável e manutenível
  • Configuração centralizada de conta PayPal, moeda, montantes, nome, logo e URL
  • Usar a stack existente do projeto; se for hospedagem estática, implementar a solução estática suportada e documentar qualquer backend mínimo necessário com variáveis de ambiente seguras

5. Configuração

  • Nome do projeto: [PROJECT_NAME]
  • Logo: [LOGO_URL_OR_FILE]
  • Conta PayPal: [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID]
  • Moeda: EUR
  • Mínimo: [MINIMUM_AMOUNT]
  • Montantes sugeridos: [2, 5, 10, 25, 50]
  • URL principal: [PROJECT_WEBSITE_URL]
  • Contacto: [CONTACT_EMAIL]
  • Idioma: pt-PT

6. Critérios de Aceitação

  1. Todos os montantes predefinidos são selecionáveis
  2. Valor livre válido é aceite
  3. Valores inválidos são rejeitados com explicação clara
  4. Montante e moeda chegam corretamente ao fluxo oficial do PayPal
  5. A conta designada recebe a doação (sujeito à configuração da conta e conclusão da transação)
  6. Cancelamento é tratado com elegância
  7. Pagamentos bem-sucedidos nunca são reportados falsamente
  8. Página funciona em mobile e desktop
  9. A conta PayPal muda por configuração, sem redesenho
  10. Instruções de setup incluem ligação e teste real (sandbox quando suportado)

7. Entregáveis

  • Código-fonte completo e funcional
  • Página de donativos responsiva
  • Integração PayPal real (não maquete visual)
  • Instruções de configuração, deploy e testes (sucesso, cancelamento, valores inválidos)
  • Lista clara de pré-requisitos/limitações da conta PayPal e de passos que dependem de credenciais ou aprovação do dono do projeto

Antes de implementar, inspecionar a estrutura existente e reutilizar o design system e a stack atuais sempre que possível.

Prompt — Create a Donation Page with One-Time and Recurring PayPal Giving (USD)

1. Project Objective

Create a modern, responsive donation page for an independent digital project that supports both one-time donations and recurring monthly giving through PayPal.

The page must let visitors choose a preset amount or a custom amount, decide whether to give once or monthly, and complete the payment through PayPal's official flow. Default currency: USD ($).

The page must communicate trust and transparency, work for an international audience in English, and never claim a payment succeeded before PayPal confirms it.

2. Donation Functionality

Giving frequency

Two mutually exclusive modes, visually prominent:

  • One-time (default)
  • Monthly — short copy explaining recurring support: "Monthly support lets us plan ahead and keep improving the project."

Changing frequency must not lose the selected amount.

Preset amounts (one-time)

  • $3 — Coffee
  • $10 — Supporter
  • $25 — Contributor
  • $50 — Champion
  • Custom — any amount

Preset amounts (monthly)

  • $2/mo — Supporter
  • $5/mo — Sustainer
  • $10/mo — Patron
  • Custom monthly amount

All amounts configurable. Selecting "Custom" reveals a numeric input.

Custom amount rules

  • Currency: USD by default
  • Validate before redirect: reject empty, zero, negative, non-numeric, below configurable minimum
  • Show a clear summary: "$25 one-time" or "$5/month" before redirect
  • No card data collected or stored on the site; no automatic charges outside PayPal's own flow

PayPal integration

  • Merchant/PayPal account: [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID]
  • Use PayPal's official support for recurring billing (Subscriptions/Donations with a plan) and one-time Checkout/Donate. Verify which products your account is eligible for; do not assume PayPal.me supports these features.
  • Flow: choose amount + frequency → summary → official PayPal interface → complete or cancel → return to success/cancel pages when supported.
  • Never simulate success. Never expose secrets in frontend code; if a backend is required, keep credentials in environment variables and implement the minimum secure backend.

3. Page Design

Modern layout, professional typography, consistent with the existing project's design system (reuse it if present).

A. Hero

Headline: "Keep This Project Growing." Supporting text: "Your donation pays for maintenance, new features, and infrastructure. Give once or make it monthly — every bit helps." CTA: "Donate with PayPal"

B. Donation selector

Segmented control: One-time | Monthly. Amount cards with amount, friendly label, selected state, accessible interaction. Custom amount field. Live summary line above the CTA showing amount + frequency + currency.

C. Where your support goes

Configurable list (e.g., maintenance, new features, hosting). Only claims approved by the project owner.

D. Trust block

Payments processed by PayPal; site never stores card details; donations voluntary; state explicitly whether monthly giving can be cancelled anytime (only if true and supported by the chosen PayPal product).

E. Thank-you state

Confirmed state: "Thank you for your donation — it really helps." Neutral state otherwise: "Thank you for visiting our donation page." Return-to-site button.

4. Technical Requirements

  • Responsive, accessible, keyboard navigable, clear validation errors
  • Frequency and amount both passed correctly to PayPal (recurring amounts must create a recurring agreement/plan, not a one-time payment)
  • SEO metadata, fast load, lightweight assets, maintainable code
  • Centralized config; reuse existing stack; static hosting preferred, backend only if the integration requires it (documented)

5. Configuration

  • Project name / logo / website URL / contact: [PROJECT_NAME], [LOGO_URL_OR_FILE], [PROJECT_WEBSITE_URL], [CONTACT_EMAIL]
  • PayPal account: [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID]
  • Currency: USD
  • One-time amounts: [3, 10, 25, 50]
  • Monthly amounts: [2, 5, 10]
  • Minimum donation: [MINIMUM_AMOUNT]
  • Default language: English

6. Acceptance Criteria

  1. Every preset amount works in both frequencies
  2. Custom amounts validate correctly (empty/zero/negative/below minimum rejected with clear messages)
  3. Summary always shows correct amount + frequency + currency before redirect
  4. One-time → one-time PayPal payment; monthly → recurring PayPal agreement (verified in sandbox)
  5. Cancellation handled gracefully; no false success messages
  6. Works on mobile and desktop
  7. PayPal account, amounts, and frequencies changeable via configuration only
  8. Setup guide covers sandbox testing for both payment modes

7. Deliverables

  • Complete working source code and responsive page
  • Real PayPal integration for one-time and recurring flows (no visual mock-ups)
  • Configuration, deployment, and testing instructions (success, cancellation, invalid input, recurring cancel)
  • List of PayPal account prerequisites/limitations and every step requiring merchant credentials or approval

Prompt — Create a Transparent Funding Page for an Open-Source Project with PayPal

1. Project Objective

Create a funding page for an open-source project that lets users support maintenance and development through PayPal, while publishing a transparent, honest view of how funds are used.

Audience: developers and GitHub users; language: English; currency: EUR by default but configurable. Tone: factual, humble, no marketing hype.

The page must be honest about what donations do and do not buy (e.g., no promises of delivery dates tied to donations).

2. Funding Model

Contribution options

  • Preset amounts: €3, €10, €25, €50, €100 — labels describe impact, not guarantees (e.g., "covers infrastructure for a month" only if verified as accurate)
  • Custom amount (validated: not empty/zero/negative/non-numeric; configurable minimum)
  • Frequency: one-time (default) and optional monthly via PayPal's supported recurring product, if available for the account

Transparency ledger (required)

A public section, data-driven from a single config/JSON file, showing:

  • Funding goal per period (configurable) and current progress
  • Cost breakdown rows (hosting, CI minutes, domains, tooling) with amounts
  • "Last updated" date; ability to show as manual entry (no scraping) — values must be marked as estimates unless audited

Never fabricate numbers: if a field is unknown, render it as "—" or hide it.

PayPal integration

  • Account: [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID]
  • Official PayPal Donate/Checkout flow with preset amount passing; verify capabilities before choosing the product
  • Summary → official PayPal page → complete/cancel → return URLs
  • No fake confirmations; no secrets in frontend; minimum secure backend with env vars if required

3. Page Sections

A. Hero

Headline: "Fund the Tools You Depend On." Text: "This project is free to use. Donations pay for hosting, CI, and maintenance time." CTA: "Donate via PayPal" + secondary link: "View funding transparency" (anchor)

B. Donation selector

Amount cards + custom input + optional frequency toggle + live summary + "Continue with PayPal". Selected state obvious, accessible, keyboard-friendly.

C. Transparency ledger

The data-driven table/progress bar described above, with a link to the config source (e.g., the JSON file in the repo).

D. What donations do NOT buy

Explicit honest block: no paid support SLAs, no guaranteed features, no tax-deductible status unless verified.

E. Other ways to help

Stars/issues/contributions links — funding is one option among several.

F. Thank-you

Confirmed: "Thank you for keeping this project alive." Neutral fallback otherwise. Return link to project homepage.

4. Technical Requirements

  • Responsive, accessible, SEO-friendly, fast, lightweight
  • Progress/ledger data externalized (single config file, documented schema)
  • Centralized config: project name, logo, repo URL, PayPal account, currency, amounts, minimum, goal values
  • Reuse existing stack/design system; static-hosting friendly
  • Validation with clear errors; no payment data on site; no false success states

5. Configuration

  • [PROJECT_NAME], [LOGO_URL_OR_FILE], [PROJECT_WEBSITE_URL], [REPO_URL], [CONTACT_EMAIL]
  • PayPal: [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID], currency EUR, amounts [3, 10, 25, 50, 100], minimum [MINIMUM_AMOUNT]
  • [FUNDING_GOAL], [FUNDING_BREAKDOWN_JSON], [LEDGER_UPDATED_AT]
  • Language: English

6. Acceptance Criteria

  1. All preset and custom amounts selectable and validated
  2. Amount + currency reach PayPal correctly; cancellation graceful; no false success
  3. Ledger renders entirely from config — editing the JSON updates the page without code changes
  4. No unverifiable claims (tax, SLA, delivery dates) appear anywhere
  5. Mobile + desktop OK; account changeable via config only
  6. Setup guide includes sandbox testing and how to update ledger data

7. Deliverables

  • Full source code, responsive page, real PayPal integration
  • Ledger schema + example config file + update instructions
  • Deployment and testing instructions
  • Prerequisites/limitations list; clearly flag steps needing merchant credentials or account approval

Inspect the existing repo first; reuse its design system and stack.

Prompt — Minimal One-Section PayPal Donate Page (Single File, Static Hosting)

1. Project Objective

Build a minimal, single-section donation page that ships as one static HTML file (inline CSS/JS or one CSS + one JS file), ready for GitHub Pages or any static host, integrating PayPal for donations to [PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID].

Design philosophy: one screen, zero clutter, loads instantly, works without JavaScript beyond the donation interaction. English, EUR default.

2. Donation Functionality (scope-limited on purpose)

Exactly this interaction, nothing more:

  1. Row of amount chips: €5 · €10 · €25 · €50 + Custom (single-select, one active at a time)
  2. Custom chip reveals a compact number input
  3. Summary line: You're giving €10 via PayPal
  4. Button: Donate with PayPal → official PayPal payment flow with the chosen amount
  5. Return link/button on success and cancel landing states (PayPal return URLs if the chosen product supports them)

Rules:

  • Validate: reject empty/zero/negative/non-numeric; configurable minimum (default €1)
  • Show chosen amount before redirect; no card data on the page; no fake success screens
  • Configuration object at the top of the JS file:

  const DONATION_CONFIG = {

    paypalAccount: '[PAYPAL_ACCOUNT_EMAIL_OR_MERCHANT_ID]',

    currency: 'EUR',

    amounts: [5, 10, 25, 50],

    minimum: 1,

    projectName: '[PROJECT_NAME]',

    websiteUrl: '[PROJECT_WEBSITE_URL]'

  };
  • Use an official PayPal-supported mechanism for passing a dynamic amount (PayPal Donate button with hosted button id, or PayPal.me with amount if your verification shows it supports it, or a PayPal Checkout JS integration). Verify first; document which one was chosen and why in the README section of the file comments.

3. Visual Spec (compact)

  • Max-width ~560px card, centered, generous padding, system font stack or the project's existing font
  • Headline: "Support [PROJECT_NAME]"
  • One supporting sentence; no long sections, no accordion, no images beyond optional 40px logo
  • Chips: pill buttons with clear selected state (border/fill), :focus-visible ring, min touch target 44px
  • Amount chips as radio semantics (role="radiogroup" / aria-checked) for accessibility
  • Footer line: "Payments are processed by PayPal. We never see your card details."
  • Light + dark mode via prefers-color-scheme, respecting the host site's palette tokens if present

4. Technical Requirements

  • Static-hosting compatible (GitHub Pages): no backend unless strictly required — if required, provide the minimum secure implementation with env vars
  • No frameworks; vanilla HTML/CSS/JS; total page weight target < 50 KB excluding PayPal scripts
  • Accessible (keyboard, ARIA, contrast), responsive from 320px up
  • SEO: title, meta description, Open Graph basics
  • Centralized DONATION_CONFIG; changing the PayPal account or amounts = editing one object

5. Deliverables

  • Single-page source file(s)
  • Inline configuration instructions as comments at the top of the file
  • Short testing checklist: each preset chip, custom valid amount, invalid amounts, PayPal redirect, cancel path
  • Notes on PayPal prerequisites (which integration used, sandbox steps, account flags needed)

Do not deliver a mock-up: the Donate button must trigger the real PayPal flow. Flag any step that needs merchant credentials or account configuration by the owner.
