## Q218 — Boundary Value Analysis

Current key appears to be:

`C: 1, 2, 98, 99`

The question concerns **two-value Boundary Value Analysis for a valid range 1–99**.

Under CTFL v4.0.1 two-value BVA, values should exercise each boundary and its closest neighbor in the adjacent partition.

Expected set is therefore likely:

`0, 1, 99, 100`

If the existing option D contains this set, the expected answer should be D.

Before changing it, verify against the official CTFL v4.0.1 definition/example of two-value BVA.

Then update:
- `correctAnswer`
- explanation
- correct/incorrect feedback
- option explanations
- exam tip/memory aid if they teach the wrong BVA rule.

Do NOT confuse two-value BVA with older interpretations that select two values inside the valid partition.

# Important BVA rule

Never apply BVA without identifying:
1. the equivalence partitions;
2. the boundaries between partitions;
3. whether the question requests 2-value or 3-value BVA.

For 2-value BVA, verify the exact CTFL v4.0.1 definition before choosing values.

Do not assume that selecting two values *inside* a valid range around each endpoint constitutes correct two-value BVA.

---

# Important EP rule

For equivalence partitioning, distinguish between:

- **coverage of individual equivalence partitions**, and
- **coverage of combinations of partitions across multiple parameters**.

Do not require the full Cartesian product unless the requirement/question explicitly calls for combination coverage or another technique that requires it.

Multiple values from the same partition do not increase basic EP partition coverage.

---

# Error / defect / failure / root cause

Keep these concepts distinct.

Conceptually:
- **Error**: human action/mistake that produces an incorrect result.
- **Defect**: flaw/imperfection in a work product.
- **Failure**: externally observable deviation during execution.
- **Root cause**: fundamental reason a problem occurred.

Use the exact official syllabus definitions when available.

Scenarios must identify whether they are referring to the human mistake or the resulting flaw in an artifact.

# Conservative-change policy

This is important because the model performing this task may be inexpensive.

**DO NOT rewrite hundreds of questions just to improve wording.**

Only modify a question when at least one of these is true:

- answer key is wrong;
- more than one answer is correct;
- no answer is correct;
- question is impossible to answer from the supplied information;
- explanation/feedback contradicts the answer;
- mathematical/logical reasoning is wrong;
- terminology materially conflicts with CTFL v4.0.1;
- metadata is demonstrably wrong;
- ambiguity materially affects which answer is correct.

If a question is merely stylistically imperfect but technically correct, leave it alone.

When uncertain, put it in the audit report instead of making a speculative edit.
